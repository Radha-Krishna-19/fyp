Why this is the question that matters. Every quantitative result on this page above this point was computed on hMOF-### entries: chemically plausible, combinatorially assembled, never synthesised. A band that only holds for one generator’s output is a statement about that generator, not about matter. The only way to tell the difference is to run the same code on structures that came out of a laboratory — enough of them to be a distribution rather than an anecdote.
Everything below this point compares two bands that are both withdrawn. As set out above, Δα does not converge with supercell size on the coarse-grained quotient graph, and both this 61-framework band and the 77-framework hMOF band were in fact computed on the atomic supercell graph, not the coarse-grained graph this site describes — which additionally spans two length scales (molecular and framework) that a single power-law fit cannot legitimately span. The comparison below is kept, with this notice, because the question it asks — does a band calibrated on one dataset transfer to another — is a reasonable one to have asked, and the negative answer about convergence does not depend on which dataset the non-converged number came from. Read every number below as “two non-converged quantities agree with each other”, not as a chemical or structural finding.

Sub-Bands (Narrow/Medium/Wide) Are Size Strata, Not Chemistry

A teammate's separate coarse-grained run cut the 76-structure hMOF set into three classes — Narrow, Medium, Wide — by the 25th and 75th percentiles of Δα. This section checks what those labels actually track.

These classes were already flagged as unsound in PROJECT_NOTES.md before this analysis: the Medium class is 0.032 Δα wide against per-structure error bars of 0.013–0.098, and the run's own isomorphism check found hMOF-94 and hMOF-96 to be the identical graph — yet they landed in different classes. Two separate findings, and they point the same way for different reasons. Where the coarse-grained graph genuinely differs in size between structures, class membership is completely explained by that size — not partially, not mostly, completely, for every one of the 13 distinguishable groups in this sample. Where the coarse-grained graph is identical — the majority case, 48 of 76 structures — class membership is decided by something coarse-graining cannot see at all: box-covering trial noise on a descriptor (Δα) already shown elsewhere on this page not to converge with size. Neither case supports reading Narrow/Medium/Wide as a chemical or structural distinction. In the first case the label restates a number already reported (node count); in the second it restates nothing, because the input to the classifier is uninformative by construction.
Why coarse-graining cannot see the difference among the 48. Coarse-graining collapses every atom in a building block to one vertex and keeps only which blocks are bonded to which. The 48 hMOF structures in this group are built from the same net (pcu), the same node (Zn₄O), and differ only in linker chemistry — which SMILES string the organic strut is. That is exactly the information coarse-graining discards by design (see the Methodology page's discussion of which graph the spectrum is taken on). A method that cannot see linker chemistry cannot separate frameworks that differ only in linker chemistry, and it does not: it produces the same graph, computes the same statistics, and any apparent difference in the resulting Δα is measurement noise.

Does the Divergence Slope Itself Vary Between Frameworks? A Proposal, Not a Result

The Methodology page lists reporting the Δα(D) growth slope as one of two ways forward once the width itself is known not to converge. This section takes a first, capped look at whether that slope actually differs between frameworks — which it would have to, to be worth proposing.

What was run, and what was not. Twenty structures per dataset, chosen for size spread rather than sampled at random or taken in full (the full 77/61 would cost far more than this check needs). Supercell replication capped at 5000 nodes. A three-point sweep (n = 2, 3, 4) with one seed, not the five-point, three-seed sweep used for the single-structure convergence figure above — enough to fit one slope per structure, not enough to know that slope precisely. This trades per-structure precision for coverage across many structures on purpose: the question here is whether the slope varies between frameworks at all, not what any one framework's slope equals to three decimal places. Several structures were dropped where the size cap left fewer than two usable points (2_python/code_15_dataset_sweeps.py reports each one).
The slope varies about 2.5× more across CoRE MOF than across hMOF, at this sample size and this precision. That is consistent with the slope carrying real structural information the width does not — the hMOF set is dominated by one degenerate, repeated topology (see the sub-bands section above), so a tight slope distribution there is exactly what a topology-driven slope should look like, while CoRE MOF's real topological variety would be expected to spread the slope out. It is also consistent with the CoRE MOF spread being sampling noise from the coarser, one-seed, 20-structure sweep; nothing here distinguishes those two explanations, and doing so needs the same multi-seed, full-sweep rigour code_12 applies to one structure at a time, run across many. This is a candidate worth pursuing, stated as one, not a second descriptor to add to the withdrawn list above.

The word “band” has been used loosely on this page. Here it is pinned down: three different definitions, the numbers for each dataset under each, and an honest account of what such a band can and cannot be used for.

The table and the four uses below describe both bands as they were computed — which is to say, as artefacts. Kept for the record and to make concrete what “a band” would look like if Δα converged. None of the four uses below is actually available today; the fourth was already marked unsupported before this withdrawal, and the withdrawal removes the other three as well.

First: “band” is three different claims

A range can be quoted as the full extent of the data, as the middle half, or as a central interval that discards the tails. They are not interchangeable, and quoting one while implying another is a standard way to overstate a result. All three are given below so the reader can pick.

The two bands agree on their centre and disagree on their spread. Medians 1.197 against 1.214; means differing by 0.018, which a Welch test cannot distinguish from zero (p = 0.38). But the synthesised standard deviation is 0.132 against 0.095, and a Levene test can distinguish those (p = 0.010). Real frameworks are more varied than generated ones — which is the expected direction, and worth stating because the usual worry runs the other way, that a hand-curated set will be artificially narrow.

What a band is for — four uses, none of them currently supported

1. A null range not supported

You cannot call a framework “unusually heterogeneous” without knowing what usual is, and a band would supply that reference — if it were a property of the frameworks rather than of the graph it happened to be measured on. Since Δα drifts with supercell diameter without bound, there is no fixed “usual” to compare a new structure against; the answer would depend on how large a graph the new structure's pipeline run happened to build.

2. Pipeline quality control partially usable

A framework whose spectrum fails to compute at all, or whose linearity R² collapses, still flags a broken CIF or a disconnected supercell — that check does not depend on Δα being converged. But using a specific Δα range as the flag (as the 39 rejected structures in this run were) is not defensible until the range is defined at a fixed, stated graph size.

3. Transfer from cheap data to real materials not supported

The two bands coinciding was read as evidence that a rule calibrated on hMOFs applies to real MOFs. It is now understood as two copies of the same size-dependent artefact agreeing with each other — unsurprising, since both were computed the same way on graphs of overlapping size. This does not establish transfer.

4. Screening candidates not supported

The aspiration is to triage candidates before spending hours of simulation on them. That requires Δα to correlate with a property someone wants, and nothing here demonstrates that — and it requires Δα to be a fixed number for a given framework in the first place, which the convergence finding above shows it is not. This use was already unsupported before the withdrawal; the withdrawal removes any route to supporting it without a redefinition of the descriptor.

How discriminating is the band, really? The question is moot: a band expressed as a fixed numeric range (such as the combined interquartile band 1.10–1.26 quoted in the table above) is not well-defined once Δα is shown to depend on supercell diameter without bound. Any pass/fail threshold quoted from this table describes the sample that was measured, at the graph sizes it happened to be measured at, not a property a new structure can be checked against.
This page previously gave a rule of thumb for reading a new framework's Δα against the band above. That rule is withdrawn along with the band it was based on. Until a size-independent descriptor is defined and its own reference range is measured, there is no number this project can responsibly hand you to compare a new CIF's Δα against.

0How Those Sixty-One Frameworks Were Obtained

The route to real structures had to be rebuilt twice: once because the database returned the wrong records, and once because the service stopped returning records at all.

You know
That the two bands coincide.
This section
Explains where those 61 real structures came from, and the two separate failures that made getting them hard.
Which lets us
Judge the provenance of the data, which is the part most easily faked and least often shown.

The bug that made this necessary

The analysis notebook was always written to pull CoRE MOF 2019 — experimentally derived, solvent-removed crystal structures. It asked the MOFX-DB API for exactly that. What came back was hMOF records, and that is why every quantitative result in this project was, for months, computed on hypothetical frameworks.

The cause: on that endpoint the database= parameter is advisory, and when it is combined with a gases[] filter the gas filter wins. The request was correct; the response simply did not honour it. A provenance check further down the notebook caught the discrepancy and printed a warning — which is the only reason we know, rather than having published “experimental” results computed on generated structures.

Then the API stopped answering entirely. The corrected query — which filters every returned record on its own database field rather than trusting the server — began returning zero records. A query that returns nothing is at least honest, but it does not produce a dataset.
Fixed by removing the dependency. The structures now come from the Zenodo archive of CoRE MOF 2019, DOI 10.5281/zenodo.3370236, downloaded by DOI rather than queried. An archived record is immutable and citable: it is the same bytes for every reader, permanently, which is a stronger provenance guarantee than any live endpoint can offer. Sampling is capped per metal composition so that no single metal can dominate the set the way Zn dominated the 77.

The procedure, which ran unchanged

Every module from bond perception onward is written per-CIF and is indifferent to where the CIF came from. Moving from hypothetical to real structures required no change to the analysis — only to the source of the data. That is worth stating plainly, because it is the reason the two sets are comparable at all.
