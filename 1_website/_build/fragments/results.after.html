0The Same Analysis on Real, Synthesised MOFs

The band above is built from hypothetical frameworks. This section runs the identical pipeline on MOFs that have actually been made in a laboratory, expanded under the identical supercell rule so the two sets are comparable rather than differing by size.

What changed, and why it is a fair comparison. These four structures appear elsewhere on this site as small unit cells, used to demonstrate the decomposition. Here they are expanded under the same rule the 77 frameworks were expanded under — every lattice direction grown past 48 Å — which brings their block counts into the range the hMOFs occupy. Without that step the comparison would be measuring graph size, which is exactly the confound that removed the pore-size claim earlier on this page.

How to read this

Two readings are consistent with the gap, and the four structures here cannot separate them.

Reading 1 — the descriptor is working

hMOF structures are assembled combinatorially from a small library of building blocks into regular topologies, so their pore networks are unusually uniform. Real frameworks have more varied local environments, which is precisely what a wider singularity spectrum reports. On this reading Δα is measuring something chemically real, and the gap is the descriptor doing its job.

Reading 2 — four is not enough

Four structures chosen because they are famous are not a random sample of synthesised MOFs. All four are archetypes, picked for high symmetry and clean topology. It is possible that a broader sample of real frameworks would overlap the hMOF band after all, and that these four are simply unusual.

What this does establish, stated carefully. A band fitted on hypothetical frameworks would reject all four of these real materials. Whichever reading is right, that is a warning worth recording: a screening rule calibrated on generated structures cannot be assumed to transfer to materials that exist. Distinguishing the two readings needs a proper sample, which is the next section.

0Scaling the Comparison to Fifty Real Frameworks

Four synthesised structures show a clean gap. Four is not a sample. This is the concrete plan for turning that observation into a result, and the bug fix that unblocked it.

The bug that caused this in the first place

The analysis notebook was always written to pull CoRE MOF 2019 — experimentally derived, solvent-removed crystal structures. It asked the MOFX-DB API for exactly that. What came back was hMOF records, and that is why every quantitative result in this project has been computed on hypothetical frameworks.

The cause: on that endpoint the database= parameter is advisory, and when it is combined with a gases[] filter the gas filter wins. The request was correct; the response simply did not honour it. A provenance check further down the notebook caught the discrepancy and printed a warning — which is the only reason we know, rather than having published "experimental" results computed on generated structures.

Fixed. The fetch now filters every returned record on its own database field and discards anything that is not CoRE MOF, rather than trusting the server-side parameter. The limit was raised so that enough survive the filter, and the run prints how many records were streamed, how many were kept, and what was discarded. Asking politely is not a provenance guarantee; checking each record is.

What we predict, recorded before the run

If reading 1 holds

Fifty CoRE MOF structures of matched graph size cluster around Δα ≈ 1.7–2.3, above the hMOF band, and split by metal or by underlying net. That would make the gap a real property of synthesised frameworks and the descriptor genuinely informative.

If reading 2 holds

They scatter broadly and overlap the hMOF band, showing that our four archetypes were unrepresentative. We would report that, withdraw the gap the way we withdrew the pore-size claim, and say so on this page.

The procedure, which runs unchanged

Every module from bond perception onward is written per-CIF and is indifferent to where the CIF came from. No code change is required — only data.
