The Decomposition Algorithm

The published metal-oxo decomposition, module by module, with the real code beside a live 3D model.

1The Full Pipeline — Code + 3D, Module by Module

Start at Module 1 and work forward — each module shows its real source (verbatim excerpts, real line numbers) beside a live 3D model of HKUST-1 that updates to match. Use the module tabs to jump around, or Previous/Next to move through all 16 steps in order.

You know
That a framework should be treated as a graph of building blocks.
This section
Performs the first real step: reading a crystal file, deciding which atoms are bonded, and cutting the structure into nodes and linkers. Runs live on any CIF you upload.
Which lets us
Build a graph at all — without blocks there are no vertices.
What you are looking at. The metal-oxo algorithm exactly as published by the Snurr group (Northwestern) in snurr-group/mofid — the reference implementation the field currently uses. Nothing here is modified: this is a visualisation of the published pipeline, stepped through one module at a time so the node and linker assignments the later network analysis depends on can be inspected directly.
Honesty note: the real MOFid pipeline is C++, which cannot execute inside a browser. Every code panel below shows this folder's own Python translation of the real algorithm (code_XX.py — every one of them is a real, runnable file you can execute yourself: python3 code_04a_metal_oxo_algorithm.py HKUST-1.cif) rather than raw C++. The 3D model itself is driven by a separate, JS port of the same logic (mof_decompose.js) so it can run live in your browser. Both were checked against each other and against known crystal chemistry (e.g. HKUST-1's [Cu][Cu] paddlewheel nodes) before being used here.
