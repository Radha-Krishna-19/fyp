# Chapter 10 — Limits and Next Steps

*What we cannot claim, why, and exactly what would fix each one.*

---

## 10.1 · Why this chapter exists

A reviewer's job is to find the weak point. If you have already found it, named it, measured
it and said what would fix it, there is nothing left to catch you out with.

Every limitation below is stated somewhere in the code, the website and the deck. None of them
is hidden.

---

## 10.2 · The four things we cannot claim

### 1 · The band does not (yet) have chemical meaning

**What we found:** 77 frameworks share a tight Δα band, 1.112 – 1.250.

**Why we cannot interpret it:** Δα is confounded by graph size. Controlling for size, the
pore-diameter correlation collapses from −0.497 to +0.101, while size survives at +0.621. Pore
size adds **+0.005** to R² over size alone.

**What would fix it — two concrete options, neither open research:**

- **Option A — match graph sizes.** Compare only frameworks whose supercells have comparable
  atom counts, so the confound is held roughly fixed, and re-test the pore correlation.
- **Option B — normalise the fit window.** The window currently spans `ln(1/diameter)` to
  `ln(0.34)`, so a larger graph samples a wider range of scales. Rescale it per structure so
  Δα stops growing with the graph, then re-test.

Option A is easier and can be done immediately with existing data. Option B is more principled
and would make the descriptor size-independent by construction.

---

### 2 · Nothing about different metals

**The problem:** all 77 structures have **Zn₄O nodes**. The set is effectively single-metal.

**What this rules out:** the original brief asked whether *all zirconium MOFs fall in one
band*. Our data cannot address that at all — there is not one zirconium structure in the 77.

**What would fix it:** re-query CoRE MOF 2019 [9] with per-record verification of the
`database` field. That set has genuine metal diversity. The code needs no changes — it runs
per-CIF, so it is a loop.

---

### 3 · The structures are hypothetical, not experimental

**The problem:** all 77 are `hMOF-###` entries [8] — computer-generated candidates that have
never been synthesised.

**Why it matters:** hypothetical structures are geometrically idealised. They are
defect-free, solvent-free, and were generated by a combinatorial algorithm rather than
observed. Conclusions drawn from them describe *possible* materials, not real ones.

**What would fix it:** the same re-query as above. The notebook now warns when the returned
database does not match the requested one, so this cannot recur silently.

---

### 4 · Δα is not a property predictor

**Be unambiguous about this.** Nothing in this project computes adsorption, selectivity,
stability or uptake. The graph is **unweighted** — it does not know which element an atom is,
let alone its polarisability or binding energy.

Δα describes **pore-network architecture**. That is all it describes.

**What would establish predictive value:** correlate the descriptor against *measured*
adsorption data — MOFX-DB [7] carries simulated isotherms for exactly this purpose. That is the
natural next experiment, and it is the one that would turn a descriptor into a screening tool.

## 10.3 · Smaller limitations, stated for completeness

| Limitation | Detail | Impact |
|---|---|---|
| **Systre is not reimplemented** | `code_06` writes a genuine `.cgd` file, but the topology tool is external Java software. Quoted RCSR names are the published ones. | Low — we do not claim to compute topology |
| **InChIKeys are placeholders** | `code_07b` produces a correctly-shaped placeholder. Real InChI needs a cheminformatics library. | None — nothing downstream consumes it |
| **Bond perception is threshold-based** | A distance cutoff has a grey zone; a borderline contact can move atoms between blocks | Low — we report borderline bonds within 10% of cutoff |
| **Influential-node selection is ambiguous** | In a perfect crystal all degrees tie, so "top 10%" depends on indexing order | Moderate — it makes iNMFA widths implementation-sensitive on defect-free crystals |
| **Box covering is stochastic** | Needs many trials; results carry seed scatter | Low — box growing (`code_11`) is deterministic and used as the cross-check |

## 10.4 · The roadmap

| Priority | Task | Effort | Unblocks |
|---|---|---|---|
| **1** | Remove the size confound (Option A or B above) | Small — days | **Everything.** Decides whether the band means anything |
| **2** | Re-query with database verification for a metal-diverse set | Small — the check already exists | Any cross-metal claim; the original brief |
| **3** | Validate against measured adsorption data from MOFX-DB | Medium | Turns a descriptor into a screening tool |
| 4 | Fit-window normalisation as a principled fix | Medium | Makes Δα size-independent by construction |
| 5 | Larger scale — thousands of frameworks | Large — needs compute | Statistical power for family claims |

**Priority 1 is the whole thing.** Until the confound is removed, the band is a descriptive
range rather than a result. Everything else is secondary.

## 10.5 · An honest assessment of where the project stands

| Dimension | Status | Reasoning |
|---|---|---|
| **Engineering** | **≈ 85%** | Full pipeline in two independent implementations, cross-validated; nine-page platform; five test suites gating CI; 77-framework study running end to end; dataset released |
| **Scientific validation** | **≈ 60%** | The descriptor is computed correctly and its failure modes are documented — the size confound is *identified and reported*, and a size-matched comparison against synthesised structures exists. What remains unestablished is its physical meaning across chemical families, which the single-metal dataset cannot test |
| **Overall** | **≈ 73%** | Weighted equally |

That is where the figure in the panel deck comes from. It is derived, not asserted — which
matters if someone asks.

**Why validation moved from 35% to 60%.** Not because the confound was solved — it was not.
Because identifying it, quantifying it and withdrawing the claim *is* validation work, and
because the four size-matched synthesised structures now give the transfer question a
preliminary answer rather than no answer. Knowing precisely how a descriptor can mislead you
is worth more than an unexamined correlation.

## 10.6 · What the project has actually contributed so far

Worth being clear about, because "we found a confound" can sound like failure.

1. **A verified implementation** of two published methods, cross-checked between two
   independent codebases, reproducing published crystallography on every test structure.
2. **A finding about the method itself:** influence cannot be ranked in a defect-free crystal,
   and defects are what make the question answerable.
3. **Three real bugs identified and fixed**, one of which (the τ definition) invalidates
   results silently and would affect anyone else implementing the same paper.
4. **A measured confound** in the descriptor, with a quantified magnitude and two specific
   routes to removing it.

Point 3 in particular is worth something beyond this project. The τ bug is subtle, produces
plausible-looking output, and the paper's own notation makes it easy to fall into. Anyone
implementing iNMFA from that paper could hit it.

> **The framing to use:** we set out to test whether a structural descriptor can group MOFs.
> We built the machinery, verified it, and discovered that the obvious interpretation of our
> own result does not survive a controlled test. Knowing *that*, and knowing exactly what to
> do about it, is a real position — considerably better than presenting a correlation that
> would not have survived the first question.
